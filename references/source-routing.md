# 来源获取与回退

## 共同步骤

1. 从分享文案中提取 URL。
2. 跟随短链接跳转，得到规范链接。
3. 识别平台、来源 ID 和内容类型。
4. 各方法成功后都要核验标题、作者、正文或媒体是否非空，命令成功不等于内容获取成功。

## 抖音公共视频

1. 使用最新版 `yt-dlp` 获取元数据、字幕和视频。
2. 失败后使用 Ego Lite 或等价真实浏览器读取页面、登录状态和网络请求。
3. 如果已经配置抖音专用解析器，可在不泄露 Cookie 的前提下尝试。
4. 仍失败时，请用户提供可访问链接或有权处理的本地文件。

`yt-dlp` 对规范化 `/video/<id>` 地址最稳定。短链接应先解析；图文笔记不能假设与视频走同一提取器。

## 抖音图文或长文本

1. 优先使用 Ego Lite 或等价真实浏览器读取渲染后的作者正文、展开内容和图集顺序。
2. 同时检查页面结构化数据，校验作者、来源 ID 和图片列表。
3. 可选使用抖音专用解析器获取图片和 JSON 元数据。
4. 最后使用页面截图和 OCR，但必须排除评论、导航和推荐信息。

## 登录、验证码和 Cookie

- 优先复用用户已经登录且明确授权的浏览器会话，不默认导出 Cookie。
- 遇到验证码或人工确认时交还浏览器控制权，等待用户明确继续。
- 不绕过私密、付费、地区或访问控制。
- Cookie、签名 URL 和认证请求头不得写入日志或媒体理解包。

## 其他平台

把每个平台的差异限制在获取适配层。平台适配器只负责返回统一的来源数据：规范链接、平台、来源 ID、作者、标题、正文、媒体列表、字幕和发布时间；后续分析流程不得依赖平台私有字段。
